## 兩處疑義：看原圖解決的，沒有花任何 API 費用

先前這兩組是「留手」，因為只看 LaTeX 判不出來。**裁出那兩塊看原始像素就結案了。**

### `N Flow Acoustics` 第 942 項的 `D̂`（5 處）→ 全部是 ∂

疑義在於：物質導數 `D/Dt` 在流動聲學裡是真的存在，而這一段正是對流波動方程式。

原圖（第 38 頁）：

```
∂²B'/∂x_i² − { 1/c² [ ∂²/∂t² + ( 2v_i ∂/∂t − (v⃗×ω⃗)_i − 2 ∂h/∂x_i ) ∂/∂x_i
             + v_i v_j ∂²/∂x_i∂x_j ] B' }'
  = { [ ∂/∂x_i − 1/c² ( −(v⃗×ω⃗)_i − 2 ∂h/∂x_i + v_i v_j ∂/∂x_i ) ]
      · ( (v⃗×ω⃗)'_j + ‾[∂v'_i/∂t] ) }' + [ ∂/∂t (1/c²)' Dh/Dt ]'
```

⇒ 被報出來的那五個位置，原圖上**全部是 ∂**。

⚠ **而同一條式子的最後真的有一個物質導數 `Dh/Dt`** —— 直立的 D、沒有帽子。
`scan-partial.py` 舊白名單寫的「#942 真物質導數」指的就是它，探針本來就不會報它
（`\mathrm{D}` 不是 accent）。**兩者在同一條式子裡並存** —— 所以「這份文件有物質導數」
不能拿來當「這些 D̂ 是物質導數」的理由。

### `∂̄`（3 處）→ 把多出來的槓拿掉

原圖（第 8 頁）：

```
ρ̄ ∂v'_i/∂t  +  ‾‾‾‾  ∂v'_i/∂x_j  +  ∂p'/∂x_i = 0
                ρv_j
```

橫槓蓋在 **`ρv_j`** 上面（平均值），**∂ 上面乾乾淨淨**。
MinerU 把那條槓錯配到 ∂ 身上 ⇒ 拿掉是對的。

⚠ 這一組的改法跟其他不同：其他是「把讀錯的字母換成 `\partial`」，
這裡是「**把 ∂ 上面多出來的槓拿掉**」。

⇒ 順帶記一個**不在這次範圍**的錯：MinerU 把 `\overline{ρv_j}` 的槓只蓋在 ρ 上
（`\overline{{\mathsf{P}}}\mathbf{v_j}`），槓的範圍縮小了。那是另一類錯誤。

## 探針還抓不到的一類：同一個 ∂ 被讀成兩個不同字母

```
第 942 項：  \frac{ D̂ }{ Ô x_i }         分子 D̂、分母 Ô
第 802 項：  \frac{ v̂O² }{ σ̂ t² }        分子 v̂O、分母 σ̂
O 那份 #782：\frac{ ĉ g(x,y) }{ α̂ n(y) }  分子 ĉ、分母 α̂
```

**上下同形這條規則永遠看不到它們**，因為兩側不同形。

⚠ **不要靠放寬這條規則去抓。** 放寬等於「任何 accent 對 accent 的分數都算導數」，
而真的比值就是長那樣（Favre、Biot 那兩個誤報都是這個形狀）。
要抓得另立判準 —— 例如「這份文件已經確定有 ∂ 誤讀，而且分母的被微分量是座標或時間」。

**現在的處置：記在這裡，不動。** 這一類的量還沒數過。

### 🔴 修補被 reindex 洗掉了 —— 而原因是我自己的 bug（2026-08-12 21:26 實測）

**先說結論：`reindex` 沒有壞，專案文件寫的流程也沒有錯。錯的是我另開了一條
不知道合約的寫入路徑。**

```
21:26  reindex --commit（10 份）
21:28  content_list.json 被重寫
21:41  ∂ 探針：0 → 668 處，正好分佈在那 10 份
       N Flow Acoustics：帶 _pp_original_text 的項目 455 → 0
```

**真正的因果鏈：**

```
1. scan-partial --repair 直接改了 content_list.json
2. 但沒有更新 _manifest.json 的 critical_file（size ＋ sha256）
3. is_bundle_valid() 因此對這 10 份回 False
4. reindex 觸發掃描 → 看到「壞掉的快取」→ 重新解析 → 覆蓋掉修補
```

實測（2026-08-13）：259 份裡**正好 10 份**指紋對不上，就是被改過的那 10 份。

⚠⚠ **而答案就寫在 `pp/apply.py` 的檔頭第一段**，一字不差地預告了這件事：

> 為什麼要更新 manifest：`is_bundle_valid()` 會比對 critical_file 的 size 與
> sha256。**只改內容不改 manifest，快取立刻失效，下次 /scan 會重新向 MinerU
> 抓一份，把修補覆蓋掉**

⇒ 這是「**抄一份就是再造第二條會漂移的路**」的又一個實例 ——
而我前一天才在 commit 訊息裡寫下那句話。`apply.py` 知道要重蓋指紋，
我新寫的 `repair_bundle` 不知道。

**已修**（2026-08-13）：指紋的維護抽成 `pp/apply.py` 的 `restamp_manifest()`，
是唯一的擁有者；`repair_bundle` 改完內容一定叫它，而且**蓋不了章就不動內容**
（沒有 `_manifest.json` 直接 raise —— 寧可整支停，也不要留一個註定被沖掉的修補）。
