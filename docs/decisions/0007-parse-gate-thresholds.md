# ADR-0007: `parse.coverage` 會叫但不擋；`parse.checks` 只有 ERROR 擋

* **Status**: Accepted
* **Date**: 2026-08-16
* **Deciders**: PO（08-13 起懸著，08-16 依當日實測定案）

---

## Context

體檢表的六格裡有兩格填不下去，卡在「這個訊號到底算不算壞」沒有裁決。
沒有裁決的後果不是「先不填」——是 `intake` 走完只寫得起兩格，而
**沒跑過的閘門填 `pass` 就是說謊**，所以那四格只能留空。

判準要用當天的實測定，不用印象。2026-08-16 在 dker 實跑：

```
parse-check      共 317 份： OK 32 ／ WARN 283 ／ ERROR 2
coverage-check   共 317 份：門檻 5%，超標 15 份、驗不了 1 份、通過 301 份
```

## Decision

**一、`parse.coverage` 超標 → 體檢表記 `pass`，note 寫下漏詞率與漏最多的詞。
不擋流程。** `coverage-check.py` 的 exit 1 與每日體檢的紅字**照舊保留**。

**二、`parse.checks`：`ERROR` → `fail`（擋，文件不得進下一段）；
`OK` → `pass`；`WARN` → `pass`，note 寫下 WARN 的實際原因。**

兩條都是判準，不是門檻值——`--threshold` 維持 5%，不動。

## Rationale

### 一、超標的那些，主要在量它自己的對照組壞掉

> ⚠ **2026-08-16 當日訂正。** 本節第一版寫「剩下的都是圖內文字」，並寫
> 「08-16 重量的 15 份超標樣本印證同一個形狀」。**那句話是overclaim**：
> 我當時只看了工具輸出末尾印出來的 4 份，不是 15 份，而且**沒有去看工具自己
> 已經記著的查證紀錄**。裁決（會叫但不擋）不變，但理由整段換掉——
> 換成的理由比原本的強，因為它是逐份查證過的。

這支尺的算法是「PDF 文字層有的詞」減去「解析結果有的詞」。
⇒ **它有兩個母體，而出問題的一直是對照組那一邊。**

15 份超標裡有 5 份已經逐份查證並把結論寫進工具（跑 `coverage-check.py --doc X`
就會印出來）。**五份全部是假訊號，而且是五種不同的壞法：**

| 文件 | 漏詞率 | 實際原因 |
|---|---:|---|
| 2023 Differentiable Image Source | 79.1% | IEEE 頁側直式浮水印被 `pdftotext` 讀成逐字母碎片（`A c o usti cs` → `usti`）。對照組只讀出 397 詞而解析抽出 2,500 —— **分母壞了** |
| 2024 A Compact… Folded Slit | 28.9% | 雙欄版面讓 `pdftotext` 把同一段輸出兩次。**缺詞第一名是 `the`（336 次）—— 冠詞不可能被漏掉，那本身就是量錯的訊號** |
| 1979 Image method | 11.5% | 1979 年掃描件的文字層沒有詞邊界（`room acoustics` → `roomacoustics`），解析斷對了反而被算成缺少 |
| C Equivalent Networks | 10.5% | 已逐詞歸因：表格結構黏連 117 詞、內容在圖裡 73 詞、bbox 未覆蓋 91 詞 |
| 2026 On Efficient Algorithm | 10.2% | 粗體／斜體數學字型沒有可用編碼，`pdftotext` 吐出 `dddd`／`nnjj`／`mmmmmm` |

⇒ **這支尺壞的方向是單向的：對照組讀壞 → 漏詞率被推高。**
所以「超標」多半不是解析壞掉，有時候**恰恰相反**——第一份的紀錄寫得最直白：
**解析做得越好，這個數字越高。**

剩下 10 份沒有查證紀錄。從它們的漏詞樣式看，至少有幾份長得跟上面同一族
（`1991 The propagation` 的 `crosssection`／`soundpressure`／`thepropagation`
是典型的黏字；`2017 Sound Absorption Structures` 的 `annualreviews`／`columbia`／
`personal` 各 34 次是期刊每頁的下載浮水印）。⚠ **但那是我看樣式推的，沒有逐份查證**，
不得當成事實。

⚠ **原本寫的「圖內文字」只是其中一種**（`fdtd`／`omax`／`zrad` 那種座標軸標籤
確實存在）。把整批歸因成圖內文字是以偏概全。真要根治不只是「把 image 型別分開報」，
還要**先修對照組**——或者至少讓超標時同時報「對照組詞數 vs 解析詞數」，
方向一看就知道。那是另一件事，不在本決定裡。

### 一之二、這次犯的錯本身值得記著

**工具已經把答案存在自己身上了，我沒有去問它。** `coverage-check.py --doc X`
一直都會印出「已查證於某日：…根因：…出處：…」，而我當時跑的是不帶 `--doc`
的總表再 `| tail`，只看到末尾 4 份、而且那 4 份剛好都沒有查證紀錄。

⇒ **判準：對一支會叫的尺下裁決之前，先問它「你自己記了什麼」，再看樣本。**
這條跟「有權威來源時不得自己重算」是同一族（見 `docs/NEXT.md` 第 6 批）。

⚠ **exit 1 與紅字刻意留著。** 不擋流程 ≠ 不出聲。這條訊號的用途從「守門」
降級成「這份文件圖很多，查詢時要有心理準備」，但**降級不是消音** ——
消音之後，哪天真的是解析壞了也沒有人會知道。

### 二、WARN 佔 89%，一個 89% 都會叫的訊號不會有人為它停下來

```
2026-08-16   OK 32 ／ WARN 283 ／ ERROR 2      WARN 283/317 = 89%
```

`ERROR → fail`、`OK → pass` 沒有爭議。WARN 的問題是**沒有鑑別力**：
它把「空文字 2 項」和「無文字頁超過兩成」放在同一格，而前者在
教科書章節上幾乎必然發生。

把 WARN 記成 `fail` 等於 89% 的文件都進不了下一段，那不是守門是關門；
記成 `unverifiable` 更糟——那一態的意思是「沒得驗」，而 WARN 是**驗過了、
而且驗出來的東西不足以擋**。所以是 `pass`，理由寫進 note。

⚠ **note 必填。** 記 `pass` 而不留原因，就分不出「乾淨的 OK」與
「看過了決定放行的 WARN」——查帳時那兩者必須看得出差別。

### 三、為什麼今天可以定了

C Equivalent Networks 原本是三個 ERROR 之一。2026-08-16 把兩邊的人工裁定
合成一份、`apply --commit` 之後，它的 mangled 文字（#540，旋轉 90 度的圖說）
被修掉，parse-check 的 ERROR **3 → 2**。
⇒ ERROR 是**修得動的**，所以拿它當 fail 的判準是合理的：它指向真的有事可做。
WARN 不是——283 份沒有 283 件事可做。

## Consequences

* `intake` 走完可以把 `parse.coverage` 與 `parse.checks` 兩格填起來
  （六格剩四格 → 剩兩格）。**接線本身還沒做**，見 `docs/NEXT.md`。
* 每日體檢的 `parse_rc` 與 `coverage_rc` **仍然會是 1**，因為兩支工具的
  exit code 照舊。要讓每日體檢轉綠是另一件事：讓它區分「擋流程的紅」與
  「只是提醒的紅」，本決定刻意不順手改掉。
* 剩下 2 份 ERROR（`2012 -Combined wave…_CH7`、`2020 - Folded metaporous…`）
  變成真的要處理的清單，不再淹在 283 個 WARN 裡。

## 會被什麼推翻

1. **語料改變形狀。** 「剩下的都是圖內文字」是量出來的，不是定理。哪天進來
   一批圖很少而 coverage 仍然超標的文件，這條就要重查。
2. **WARN 的定義變了。** 現在的 WARN 是「空文字／空表格／空公式／無文字頁過多」
   四種混在一起。哪天有人把一種真的嚴重的情況也歸進 WARN，89% 這個數字
   還在、但「沒有鑑別力」的推論就不成立了。
   ⇒ 動 `parse-check.py` 第 128–132 行的判準時，要回頭看這一條。
