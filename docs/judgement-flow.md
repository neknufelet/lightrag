# 判斷流程：發現問題之後怎麼辦

這份文件記的不是「有哪些規則」，是**遇到一個新問題時的決策程序**：怎麼偵測、
怎麼分類、什麼時候該叫眼睛、判不準的怎麼處理。

規則會隨文件類型增加，程序不會。所以程序比規則值得寫下來。

---

## 0. 第一步不是偵測，是盤點對照源

> **一個檢查的價值上限由它的對照源決定，不是由它的比對邏輯決定。**

這是這個專案最貴的一課。8/1 整天在把比對邏輯愈磨愈細 —— 逐格比對、
`eq_normalize`、三票多數決、第三隻眼睛選型 —— 而 `pdftotext` 一直躺在那裡：
免費、全覆蓋、直接對應解析階段，從頭到尾沒被動用。8/2 才跑，第一次跑就指出
`C Equivalent Networks` 漏詞 15.2%，是全庫最大的洞，而那一整天的力氣花在
方程式上。

**邏輯再精巧，對照源不對就沒有上限可言。**

### 推論：沒有獨立對照源的檢查只能發現內部不一致

兩個 VLM 互比，只能告訴你它們一致，不能告訴你它們對。所以：

- 方程式要拿 **MinerU 當第三票** —— 它跟 VLM 的機制完全不同
- 接地檢查是拿**產出對輸入**（實體名 對 來源 chunk），不是產出對產出
- 兩隻眼睛必須**不同家族** —— 同家族的錯誤相關，等於只有一隻

### 這個專案可用的對照源

先照管線分段，再問每一段「有什麼獨立的東西可以對」：

```
PDF ──①解析──▶ content_list.json ──②建 IR──▶ chunks ──③抽取──▶ 實體/關係 ──④──▶ 檢索
```

| 對照源 | 驗哪一段 | 覆蓋 | 成本 | 抓得到什麼 |
|---|---|---|---|---|
| **PDF 自己的文字層**（`pdftotext`） | ① | 全體 | 免費 | 掉字、掉段落、掉圖說 |
| PDF 頁數與頁面尺寸 | ① | 全體 | 免費 | 頁序位移、bbox 座標系錯 |
| content_list 的型別盤點 | ② | 全體 | 免費 | LightRAG 不認得的型別 |
| 建出來的 IR | ② | 全體 | 免費 | 靜默丟棄（chart 那 184 張） |
| 來源 chunk | ③ | 全體 | 免費 | 幻覺、跨段腦補 |
| LightRAG 原始碼 | 契約 | 全體 | 免費 | 欄位順序、型別分派改變 |
| 記錄的基準（canary） | 規則 | 全體 | 免費 | 規則漂移 |
| **原始頁面圖像 + VLM** | ① | 抽樣 | **付費** | 讀錯的符號、空表格的正確內容 |
| 人 | 任何 | 極少 | 最貴 | 領域上說不說得通 |

### 排序規則

**覆蓋 × 決定性 ÷ 成本。** 前七項全部免費且全覆蓋，所以永遠先跑。付費的那一項
不是備案，是**前面幾項指出位置之後才用的工具**。

而且免費的取代不了付費的 —— 它們抓不同類的錯：

```
pdftotext 覆蓋率   抓「掉了什麼」
眼睛               抓「寫錯了什麼」
```

`∂` 讀成 `\hat{o}` 不會讓任何英文詞消失，覆蓋率永遠 100%。反過來，空表格的
正確內容也只有眼睛能給。**所以問題不是選哪一個，是順序。**

## 1. 前提：偵測器比模型更常騙你

這個專案至今記錄了 **15 次**同一類錯誤 —— 不是模型判斷錯，是
**偵測器量的東西跟我以為的不一樣**。舉三個代表：

| 現象 | 我以為 | 實際 |
|---|---|---|
| 方程式「三方皆異」 | 六個模型都讀不出來 | 裁圖 padding 用了表格的 6 點，把上下鄰居框進圖裡 |
| 實體 55% 未接地 | 抽取器在幻覺 | 來源 chunk 全是符號，字串比對沒有鑑別力 |
| `Eta_N` / `Eta_n` 判成安全 | 只差英文詞大小寫 | 我先拿掉分隔符才找詞邊界，`N` 是下標這件事被自己抹掉了 |

**但要精確：這 15 次沒有一次是偵測器算錯數字。** 分三種：

- **輸入錯** —— 裁圖 padding；tokenizer 先拆 `{`，把 `J_{0}` 弄成兩段
- **標籤錯** —— 「55% 未接地」是真的，「幻覺」是我加上去的名字
- **偵測器本身寫錯** —— 少數，例如 MANGLED 對正常英文 "be so if r is" 誤觸發

共通點是**吵得太大聲，不是太安靜**，所以手動看前幾名就會露餡。
危險的是相反方向 —— 靜默少報，那種只有靠斷言與備份檢查擋（見最後兩節）。

對應**鐵則 4：先查輸入，再查偵測器，最後才查模型**。

## 2. 偵測：先跑最便宜的，而且要跑全體

字串比對、位置比對、計數。不呼叫模型，所以免費、確定、可以跑**全部**而不是抽樣。

為什麼一定要全體：**分類需要的是母體，不是樣本**。今天方程式那題，抽樣 30 條
看到 3 條可疑，看起來是「修三條」；跑全體才發現同一種誤讀有 943 處。抽樣能
告訴你「有問題」，不能告訴你「問題是什麼形狀」，而形狀決定後面所有的處置。

```
❌  抽樣 30 條 → 3 條可疑 → 修 3 條
✓   抽樣 30 條 → 3 條可疑 → 這 3 條是什麼**種類**的錯 → 全庫掃這個種類 → 943 處
```

## 3. 驗偵測器

在相信任何一批結果之前，把排名最前面的幾個**親手看一遍原始輸入**。

要看的是：這幾個命中長得像不像同一種假陽性？

- 像 → 偵測器有系統性偏誤，先修偵測器，結果全部作廢重跑
- 不像 → 繼續

今天的實例：`\hat{\sigma}` 分類第一版說「531 個是微分算子、269 個其他」。
看了「其他」的樣本才發現它們也是微分，只是後面接 `{` 而我的正則只認字母。
第二版改用 `\frac` 位置判斷，又錯 —— 正則剖析不了配對括號。第三版寫了真正的
掃描器才對：**909 個在 frac 內、2 個是行內除法、0 個在外面**。

三版之後結論才穩定。**前兩版如果直接拿去改資料，會改壞 269 處。**

### 分類訊號的前提也要驗：位置會被上游的剖析錯誤污染

實測（2026-08-02，N Flow #957）：ω̄⃗ 的疊層重音（箭頭疊在橫槓上）被 MinerU
把**橫槓當成分數線**，一個符號拆成上下兩半——於是兩個向量各自站上「分子／
分母首位」，而那正是 ∂ 族封閉掃描用來取代符號枚舉的位置判準。

**「以位置封閉」的前提是 frac 結構本身是真的，而這個前提來自同一個會讀錯的
MinerU。** 所以結構性判準抓出來的候選仍然要過裁圖，不能因為「判準不靠符號
枚舉」就免驗。同輪另證實：判準的錨點本身也會漏（裸 `\mathcal{O}` 沒有 accent
配不到；連續兩個誤讀算子只抓得到第一個）——封閉宣告之前，先問「這個判準
自己的盲區在哪」。

## 4. 分類：按「什麼能了結它」，不是按嚴重度

這是整個流程的核心。四格：

| 類別 | 判準 | 處置 |
|---|---|---|
| **機械可窮舉** | 有一條規則，在**全體**上零例外 | 自動套用 |
| **要看圖** | 文字層沒有足夠資訊 | 呼叫眼睛（第 5 節） |
| **要領域判斷** | 語意或慣例問題，看圖也不會有答案 | 給人，附證據（第 7 節） |
| **判不準** | 沒有便宜且可靠的訊號 | 留著，不猜（第 7 節） |

### 「零例外」是字面意思

不是「大部分對」，是**一個反例就降級**。

```
∂ 誤讀      943 處全部坐在微分的分子/分母位置，0 個獨立出現   → 機械可窮舉
\mathsf{P}   23 處裡有 #1056 `∂²P/∂t² − c₀²ΔP`，那個 P 是壓力  → 降級到逐條看
```

兩者的處置完全不同，而分野只是「有沒有反例」。找反例的成本遠低於改壞資料的
成本，所以**永遠先花時間找反例**。

### 分層要分在「能區分的訊號」上

實體合併的 A/B/C 分層是這樣長出來的：

```
A  只差分隔符，大小寫完全一致        J_0 / J 0 / J0        → 零語意風險
B  只差長度≥3 的英文詞大小寫          Transmission Loss/loss → 排版慣例
C  差在下標或短記號，或 token 對不齊   Eta_N / Eta_n         → 數學裡那是意義
```

關鍵是 C 的判準：**短 token 的大小寫在數學裡帶意義，長英文詞的不帶。**
這條分野可以寫成程式，所以 A/B 能自動、C 必須人看。分層不是為了描述，是為了
讓「哪些能自動」有一條可執行的界線。

## 5. 呼叫眼睛

### 什麼時候叫

當**文字層本身缺少判斷所需的資訊**時。

實測過：純文字的判官（DeepSeek，flash 與 pro）catch rate 51% / 48% ——
換更強的模型不會改善，因為缺的不是推理能力，是資訊。這時候才需要視覺路徑。

### 怎麼叫

1. **兩隻，不同家族。** 同家族的錯誤相關，等於只有一隻。
   `eyes.py` 的 `eyes_from_env()` 在型號或家族相同時直接拒絕啟動。
2. **各自獨立看圖**，不給對方的答案。
3. **輸入先驗過。** 給模型看的東西不對，再多模型都沒用 —— 裁圖 padding 那次，
   「三方皆異」歸零靠的是把 `EQ_PAD_Y` 從 6 點改成 1 點，不是換模型。
4. **比對在「內容」層級**，不是字串層級。表格逐格比、方程式用 `eq_normalize`
   壓成符號序列。等價的 LaTeX 寫法太多，字串比對會產生大量假差異。
5. **快取。** 同一張圖不重複付費。

### 誰贏

三票多數決：MinerU / 眼睛 A / 眼睛 B。只有在**三方皆異**時才叫第四隻 ——
其餘 87% 的案例多數決已經解決，對它們付費不會改變任何結論。

### 眼睛也會錯 —— 所以是定點修補，不是整條換掉

今天的實例：式 37 兩眼一致度 0.976，但它們

- 把 `\tag{37}`（式號）丟了
- 把 `\nabla s` 改成 `\nabla_s`

而前一條式子寫著 `\vec{L} = \vec{ω} × \vec{v} − T∇s` —— `s` 是熵，`∇s` 是熵的
梯度，MinerU 是對的。**整條換掉會把眼睛的錯誤寫進去。**

所以寫回的原則是：**只替換被證明讀錯的那幾個記號，其餘一個字不動。**
凡是 MinerU 有而眼睛沒有的東西（式號、對齊結構），一律保留。

## 6. 三態，不是二態

每一種檢查的輸出都必須是三格：**通過 / 失敗 / 驗不了**。

把「驗不了」併進「失敗」會產生假警報，而假警報會讓人開始忽略警報。

```
二態   實體接地檢查 → C 檔 55% 未接地，看起來像大規模幻覺
三態   接地 / 符號型（來源全是公式，字串比對沒鑑別力）/ 可疑 → 3.4%
```

同理，收合輸出時必須報出「幾項通過未列出」——
**「沒印出來」和「沒檢查」在畫面上長得一樣**，那正是鐵則 6 要防的。

## 7. 判不準的怎麼處理

這一格最容易被草率對待，因為它沒有成就感。規則：

### 不猜、不刪、留著

- 消音不刪除（sidecar 的 `self_ref` 是陣列索引，刪一個其後全錯位）
- 判不準的方程式維持原狀，不寫入
- 判不準的實體不合併（合併不可逆）

### 把它降級成「要人看」，並且**把要看什麼準備好**

判不準之所以判不準，通常是因為證據沒攤開。攤開之後常常就能判了。

今天的實例：`X a` / `X_a` / `Xa` 原本標成「分不出來，看不懂」。
把上下文從 90 字元拉到 300 字元，定義式就出現了：

```
X_a = j·tan(k₀ℓ_a)     ← K Muffler 式 29，三個變體原文全寫 X_a
```

所以「判不準」的第一個處置是**再挖一層證據**，不是直接丟給人。

### 真的要給人看時，一次給齊三樣

```
1. 抽取器認為   模型寫的描述
2. 原文寫的     它實際讀到的字（LaTeX 先剝掉字體指令）
3. 選項         合併成 X / 不動 / 改名 …
```

而且要標**證據可靠度**。寬鬆比對命中的要標出來並註明「不要拿它當證據」——
`entity-merge review` 的三層比對（完整名稱 / 符號部分 / 延伸形式）就是為此。

### 絕不寫成「沒問題」

判不準要出現在輸出裡、要進待辦、要附上當時的證據，讓下一個人不必重做分析。
`CLAUDE.md` 的「已知待辦」就是這個用途。

## 8. 排序：按量到的代價，不是按數量

有問題 ≠ 值得修。動手前先量**它實際造成多少損失**。

實體碎片化那題：

```
388 個多餘節點（5.4%）        ← 聽起來很多
  51 組真的出現在檢索結果裡
   8 組浪費 ≥2 格
 254 組從未出現在任何結果裡    ← 合併它們的收益是 0
```

254 次不可逆操作換 0 收益。**先量再排序**，長尾通常不值得冒險。

量的方法：跑一批代表性查詢（用 `/graph/label/popular` 當種子，不要自己編 ——
編出來的會偏向你想得到的主題），統計每組實際佔掉幾格。

## 9. 寫回的條件

任何一條不成立就拒絕，而且是**整批拒絕** —— 做到一半停下來比不做更糟，
因為你不知道停在哪裡。

1. `preflight()` 通過（型別、頁序、來源對得上）
2. 現在的狀態是被認可的 —— 本來就壞的東西不要動
3. **備份存在且涵蓋每一個要刪/要改的對象**
4. 有可還原的路徑（`_pp_original_*` 系列欄位）
5. pipeline 閒置
6. 寫完後項目數不變、`is_bundle_valid` 回到真

### 備份自己也會靜默失敗

今天踩到兩個：

- `max_nodes=60` 是**靜默截斷點**。69 條邊的節點只備份到 59 條，不報錯。
  → 打到上限就讓備份直接失敗。
- `dump` 直接覆蓋同名檔案。合併後為了驗證又跑一次，蓋掉合併**前**那份。
  → 帶時間戳、拒絕覆蓋；檢查備份時掃全部時間戳檔案，不只看 latest。

**備份不完整卻宣稱成功，比沒有備份更危險** —— 你會因此放心動手。

## 10. 把發現變成斷言

留在 commit 訊息裡的發現會被重新發現。能寫成可執行斷言的就寫進
`compat-check.py`。

判準：這個發現是不是「某個外部東西保持某個樣子」？是的話就是斷言。

```
A-06   _coerce_text 讀的欄位順序不變
A-24   走 _build_ir_drawing 的型別集合是 {image, picture, drawing}
A-25   chunk_top_k 仍然控制回傳的片段數
```

而且 —— **斷言要在沒人問的時候會響**（鐵則 6）。A-16「沒有未知的項目型別」
本來就抓得到 `chart`，但整段資料層檢查被 `if a.doc:` 關著，而你只會對正在
處理的那一份指定 `--doc`。184 個 `chart` 分散在 11 份文件裡，從專案開始到
發現為止一次都沒被喊過。
